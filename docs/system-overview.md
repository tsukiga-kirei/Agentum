# 系统详细梳理介绍

## 1. 产品定位

Agentum 是一个以智能体为载体的企业工作流平台。

它和常见 AI 聊天式工作流的关键区别是：用户不是在一个聊天框里等待 AI 一次性完成所有事，而是在一条明确的业务流程中，按步骤完成输入、确认、追问、审核、回退、暂停、恢复和交付。每个节点负责具体任务，每个智能体节点只在明确上下文里使用当前主体可用能力池中的 Skills、MCP、提示词模板和模型配置。

核心目标：

- 让企业 SOP 可以被拆成可执行、可暂停、可审计的步骤。
- 让智能体能力可复用、可分配、可版本化。
- 让并行子智能体加快数据获取和分析，再由合并节点组装结果。
- 让最终结果能落到 Word / Excel / PDF、邮件、OA、IM、Webhook 或数据库等交付目标。
- 让业务用户看懂自己正在做哪一步，而不是被复杂编排、变量和工具配置打扰。

第一阶段暂不推进知识库 / RAG 作为核心功能。阶段二将以**知识资产**为主线重新引入：企业文档上传、分块、版本、检索与智能体引用，并纳入与能力资产一致的权限、分配和审计模型；仓库内 `docs/` 产品文档计划作为首批样例导入验证。

## 2. 核心概念

| 概念 | 说明 |
| --- | --- |
| 租户 | 平台最高业务隔离边界，承载租户级模型额度、可用 MCP、可用 Skills、交付能力和系统策略 |
| 组织 / 部门 | 租户内人员组织结构，用于成员管理、待办分派、审核范围和数据筛选 |

| 资源范围 | 控制当前用户、部门或角色能进入哪些业务模块、流程模板、运行记录和交付物；系统能力进入当前主体可用能力池后即可用于设计与组合，用户自建能力和流程额外区分读取 / 使用权限与内容编辑权限 |
| 智能体模板 | 可复用的智能体配置，包含系统提示词、Skills、MCP、模型、输出 Schema 和交互模式 |

| MCP | 外部系统、工具或数据源连接能力，例如文件读取、数据库只读查询、邮件发送、OA 创建流程 |
| 提示词模板 | 可复用的 Prompt 片段或业务话术模板，供智能体模板或节点引用 |
| 交付能力 | 生成文件、发送邮件、创建 OA、推送 IM、Webhook、写数据库等最终动作 |
| 工作流定义 | 设计态流程模板，优先按阶段积木组织，包含步骤、依赖、变量和节点配置 |
| 工作流运行 | 某一次实际执行实例，保存状态、变量快照、节点记录、暂停事件和交付记录 |

## 3. 产品区域

Agentum 不应该让所有用户进入同一个默认编排器。不同角色看到不同入口和操作。

| 区域 | 面向角色 | 主要内容 |
| --- | --- | --- |
| 认证与账号区 | 所有人 | 登录、会话过期、无权限、个人资料、账号安全、当前租户 / 角色 |
| 业务工作台 | 业务人员、执行人、审核人 | 我的待办、可用流程、我发起的流程、运行详情、待办处理、交付物 |
| 流程设计 | 流程设计者、智能体管理员 | 工作流列表、阶段积木编排、节点配置、变量、测试运行、发布校验 |
| 能力资产 | 能力管理员、智能体管理员 | 智能体模板、Skills、MCP、提示词模板、交付能力资产 |
| 运行监控 | 流程负责人、租户管理员 | 运行状态、失败重试、取消、补偿和管理员介入 |
| 运行审计 | 审计人员、管理员、流程负责人 | 只读运行记录、节点记录、变量快照、工具调用、审核记录、交付记录 |
| 租户管理 | 租户管理员 | 当前租户内的成员、部门、角色、资源范围、需求配置和可用能力分配 |
| 系统管理 | 系统管理员 | 租户、模型供应商、全局 MCP / Skills 开关、交付能力、系统参数、多租户策略 |

前端隐藏入口只是降低干扰，不是安全边界。所有接口、资源访问、发布、执行、MCP 调用、凭证和交付动作都必须由后端重新校验。

### 3.1 登录与租户选择

登录页需要同时明确“用户要以什么入口进入”和“非系统管理员归属哪个租户”。租户是平台最高业务隔离边界，业务用户和租户管理员必须在登录时选择租户，后端据此校验用户是否属于该租户、是否具备所选入口对应角色，并把当前租户写入会话或 JWT 的活跃角色上下文。审核人、流程设计者、能力管理员等属于租户内第二层权限，不作为登录页入口角色。这里的租户管理员不是平台级系统管理员，而是当前租户内的管理入口，负责租户内组织、权限和需求配置。

系统管理员入口不绑定某个租户。系统管理员登录后进入平台级系统管理，再在具体租户管理、租户可用能力池配置、租户统计或跨租户诊断场景中选择目标租户。这样可以避免把平台级操作误认为某个租户内操作。

当前登录链路要求公开接口返回活跃租户轻量列表，登录请求携带 `tenantId` 和 `preferredRole`；后端签发令牌时写入 `activeRole`、`tenantId` 和角色集合。公网 SaaS 场景下，公开租户列表可能暴露租户名称，后续可改为租户编码输入、企业域名识别或子域名识别。

首次部署时如果系统没有任何用户，应进入初始化引导页创建首个系统管理员。该流程只在 `users` 表为空时开放，创建出的账号拥有 `system_admin` 入口且不绑定租户；系统初始化完成后，再由系统管理创建租户、租户管理员和后续业务成员。开发演示账号只属于本地 `devdata`，不能替代生产初始化链路。

### 3.2 页面抽象原则

当前前端页面是为了降低用户理解成本而抽象出的产品视图，不等同于稳定的领域模型、数据库边界或最终信息架构。

页面可以随着开发推进继续拆分、合并或改名。判断一个页面是否应该保留，优先看它是否服务某类角色的具体任务，而不是看它是否刚好对应一个后端表或一个概念名。

设计原则：

- 页面是角色任务入口，领域对象是后端事实来源。
- 页面可以聚合多个底层对象，例如运行审计页可以聚合运行记录、节点记录、等待事件、审计日志、变量快照、MCP 调用和交付记录。
- 页面不应制造新的权责边界。业务处理、运行监控和运行审计应分别对应不同操作权限。
- 过渡期为了说明概念出现的面板或卡片，如果后续被具体模块覆盖，应及时移除，避免形成重复抽象。
- 产品文案优先使用业务语言，技术动作码、表名和事件名只作为次级信息或开发调试信息。
- 管理台页面应以系统管理为母版逐层展开：先统一页头与模块切换，再进入列表、详情、表单和授权矩阵；租户管理、能力资产、审计等页面保持同一视觉节奏，避免每页自定义一套导航。
- 当前静态页面里的大卡片、说明面板和概览区主要用于表达产品心智，不是生产最终页面形态。生产页面应逐步改为“左侧大菜单 + 模块内页签 / 顶层菜单 + 列表 / 详情 / 表单 / 审计记录”的结构。
- 页面改造必须保留勾稽逻辑：系统管理配置哪些能力进入租户可用能力池，租户管理再把能力池分配给用户、部门或角色；工作流引用了哪些资产，运行审计才能追溯对应版本、输入输出、工具调用和交付记录。
- 管理台列表默认使用分页查询与分页展示，页面切换、筛选和排序都基于分页参数，不再假设一次性加载全部数据。

## 4. 业务工作台说明

业务工作台是普通用户的默认入口，不默认展示设计态编排。

### 4.1 我的待办

“我的待办”表示流程已经暂停，并且下一步需要当前用户、当前角色或当前部门处理。

典型待办：

- 用户输入节点等待发起人补充资料。
- 智能体追问确认等待用户回答或确认。
- 人工审核节点等待审核人确认通过；需要修改时返回对应步骤处理。
- 高风险 MCP 调用等待审批。
- 高风险或需人工确认的交付等待二次确认；普通交付节点默认由后端运行态直接执行。

待办的核心问题是：现在轮到谁做什么。

### 4.2 运行态摘要

“运行态摘要”表示用户有权限查看的流程运行位置和状态，不一定需要用户处理。

典型状态：

- 运行中：节点正在执行。
- 已暂停：等待某人输入、审核、审批或外部回调。
- 已完成：可以查看交付物。
- 已失败：可以查看错误和是否允许重试。

运行态摘要的核心问题是：流程现在在哪里，为什么。

### 4.3 可用流程模板

可用流程模板是业务用户可以发起的已发布流程。点击后不是进入设计态编排，而是创建一次工作流运行，并进入业务态交互页面。

业务态交互页面应支持：

- 按步骤填写资料。
- 查看智能体已完成的摘要。
- 确认后进入下一步。
- 流程暂停、退出后恢复。
- 查看最终交付物。

当前实现中，用户输入和人工审核通过待办恢复流程；智能体由后端 Agent 运行态自主选择 Skill / MCP 工具并通过 SSE 输出最终 Markdown 结论。MCP 在每个模型推理回合前重新发现远端当前工具，系统管理中的工具清单只作预览和诊断，因此工具新增、删除或参数变化不依赖管理员手工刷新后才能进入下一回合。普通交付由后端执行并写入模型调用、MCP 调用、变量快照和交付记录。系统管理可把模型标记为推理模型；流程节点选择该模型后可开启深度推理，运行页把推理过程作为与 Skill、MCP 同层级的独立步骤展示，不混入最终答案。单智能体与子智能体的每轮回复展示该轮全部 ReAct 模型调用累计的输入、输出和总 Token；运行审计同时展示整次运行累计与逐次模型调用用量。系统内置交付已支持邮箱、Webhook、Word 文档和 Excel 工作簿。已保存任务允许在有权限时回退到已完成或失败节点重新生成，也支持对单智能体或指定子智能体追问续聊；高风险审批仍属于后续运行监控 / 暂停恢复能力。

### 4.4 自动执行与主动接管

流程设计者可在流程列表的详情抽屉“执行设置”中维护“允许发起人选择自动执行”，不占用积木设计页空间；设置仍保存在系统触发节点的 `allowAutoExecution` 配置中，保存后须随执行版本重新发布。未开放的流程保持逐步确认，后端也会拒绝强制自动发起请求。开放后，发起时弹窗选择逐步确认或自动执行，并可预填文本、选项和日期资料；附件仍在对应输入节点上传。

自动执行只按节点执行成功与失败判断：成功自动继续，模型正常返回“无数据”也会继续，不做业务内容完整性判断。必填输入未填写、附件或人工审核会生成待办；报错按既定上限重试，耗尽后停止。执行在后端完成，退出页面不影响运行。

主动接管保留当前执行，完成后停止自动推进。提交输入或审核通过后继续自动执行；追问、修改、采用结果后通过“继续自动执行”交还控制权。失败状态必须通过恢复或重新执行处理，点击继续不会绕过失败。

“中断执行”立即取消当前步骤并清空该步运行结果；“执行历史”可选择已执行步骤，使用“回退到此步骤重新开始”清空目标步骤及后续结果重做。执行中须先中断或接管等待结束，已完成任务不可回退。自动执行任务中断或回退后交由用户控制，后台补偿不会自行恢复；用户明确继续后才重新推进。已发生的外部交付不随回退撤销。

聊天记录与正式结果分离：首次回答成为本步正式输出，后续追问保留为候选回复，不自动覆盖业务输出变量。每个回答块可“选为本步结果”，聊天末尾的“整理完整结果”产生完整候选稿，仍需显式选择。追问后未选择就推进时，弹窗要求选择任意一条回答或先整理；后端同步阻止绕过选择直接推进。是否选中以用户明确选择为准，不按内容相同判断。正式结果变化后下游快照失效；接力集群还需重新运行受影响的后序子智能体。已成功的同内容交付会复用记录，避免恢复时重复发送。

### 4.5 业务运行详情

业务运行详情承接“我的待办”和“运行态摘要”的下一层页面。它面向发起人、当前待办处理人和流程负责人，不面向纯审计人员。

业务运行详情可以出现处理动作：

- 提交用户输入。
- 人工审核通过后继续。
- 后续可扩展回答智能体追问、确认或改写智能体输出、驳回修改、审批高风险 MCP 调用和确认高风险交付。

这些动作本质上都是“恢复暂停点”，后端必须记录恢复事件、操作人、意见、附件和来源渠道，并重新校验权限。

## 5. 流程设计积木

流程设计不以自由画布作为主要体验。Agentum 的工作流设计应像“搭积木”：左侧展示可排序的步骤积木，右侧展示当前积木的具体配置。设计者关注的是每一步谁输入、哪个智能体处理、调用哪些 Skill / MCP、输入输出参数如何衔接，以及最终如何交付。

流程设计页签第一阶段按三块组织，但生产心智应避免“工作流定义”和“发布校验”拆成两个重复列表。发布校验应作为流程详情抽屉中的治理动作出现，而不是单独占一个同质列表页。

用户自建流程的协作权限独立分为读取 / 使用与内容编辑两部分，两部分都支持仅自己、指定同事、全体同事。读取 / 使用选择“指定对象”时可按租户角色、部门或人员授权，并按当前组织关系动态解析最终可见人员；详情抽屉可查看完整人员清单及每个人的授权来源。内容编辑的“指定同事”仍只允许直接指定人员，避免角色或部门调整无意扩大流程维护权限。创建者始终拥有读取和编辑权限，编辑权限自动包含读取权限；只有创建者可以修改权限设置。获得编辑权限的同事可以持续维护流程说明、积木结构并执行发布动作，但不会因此继承流程中引用能力的权限，保存和发布时必须按当前编辑者重新校验所有引用能力。

流程的基本信息、协作权限和执行定义采用不同的变更边界：名称、简介和成员授权直接更新并记录审计，不产生新的执行版本；只有节点、连线、变量、模型、提示词、Skill、MCP 或交付配置等执行协议发生变化时，才标记为“有未发布改动”。仅移动画布位置或重复保存相同内容不要求重新校验发布。发布仍生成不可变快照，但工作流定义通过 `active_version_id` 指向当前业务可用版本；创建者可在历史版本间切换，切换只影响后续新发起任务，已有运行继续使用创建时绑定的版本。详情抽屉默认只展示最近三个版本，并始终保留当前可用版本，完整历史通过“展开全部”按需查看。

| 页签 | 目标 | 典型内容 |
| --- | --- | --- |
| 总览 | 展示可跳转的流程功能入口 | 协作开放、我的流程、新建流程、发布治理入口和近期协作流程 |
| 协作开放 | 查看他人开放给当前用户参与设计的流程 | 协作流程卡片、搜索筛选、详情抽屉、进入积木配置 |
| 我的流程 | 处理自己创建或维护的流程 | 我的草稿、发布校验、版本发布、进入积木配置 |

当前可选积木先收敛为四类：

| 积木 | 作用 | 右侧主要配置 |
| --- | --- | --- |
| 输入节点 | 收集用户输入信息 | 输入框名称、输出参数名、字段类型、占位提示、是否必填；文本和下拉字段支持可修改的预设值，日期字段支持按年、年月、年月日三级手工选择，并统一承载当前年、当前年月、上个年月、当前日期等运行时动态值；创建定时任务时可覆盖文本模板和日期取值规则，系统变量按每次计划触发时间重新计算，cron 配置实时预览下次执行时间 |
| 单智能体节点 | 运行一个智能体完成分析、生成或追问 | 选择运行模型、智能体或自定义提示词，选择提示词模板、MCP、Skill；推理模型可开启深度推理 |
| 智能体集群节点 | 组合多个单智能体协同、接力或按意图分派 | 执行方式、子智能体列表、每个智能体提示词、输出参数、意图路由、其他情况处理、拼接 / 汇总规则 |
| 交付节点 | 生成并交付最终结果 | 单/多交付项、交付方式、触发规则、交付内容 |

  ### 5.1 附件输入与内容识别

输入节点新增产品名称为“附件”的字段类型，协议字段使用 `fieldType=file`。附件字段不是把文件二进制直接写进工作流变量，而是先上传到对象存储，再把不可变的附件引用集合写入变量快照。这样可以避免大文件进入 API JSON、数据库快照和模型上下文，也便于下载权限、生命周期、重试与审计统一治理。

附件字段建议保存以下设计态配置：

| 配置 | 规则 |
| --- | --- |
| `allowedExtensions` | 必选，保存不带点的小写扩展名；启用识别时只能从当前识别方式的系统白名单中收窄，关闭识别时仍不能包含平台禁止的危险类型 |
| `maxFiles` | 单字段最多文件数，默认 5；不得超过系统上限 |
| `maxFileSizeMb` | 单文件上限；留空时继承系统值，填写时只能更小 |
| `recognitionRequired` | 识别失败是否阻止提交；默认 `true`，关闭时允许带警告继续，但下游必须能看到失败状态 |
| `description` | 告知业务用户应上传什么材料，不作为文件安全校验依据 |

启用附件识别时，所有附件字段上传后都按系统配置执行内容识别；流程设计者只配置识别失败是否阻止提交，不能在字段级关闭识别或指定识别引擎。设计器通过已登录用户可访问的附件能力接口读取当前识别方式及系统支持扩展名：启用识别时只能从系统列表中多选，字段白名单只能收窄；关闭识别时允许维护仅保存原件所需的扩展名，但仍排除平台禁止的危险类型。设计器保存前执行即时校验，发布和历史版本启用时后端再次校验扩展名、文件数、大小和识别策略。运行态取字段白名单与当前系统能力的交集生成文件选择范围，并在发起上传前拦截不允许的文件；后端继续执行同一规则作为最终防线。上传后展示“上传中 / 等待识别 / 识别中 / 已就绪 / 识别失败 / 已拒绝”，只有全部必需文件满足字段策略时才允许提交输入节点。扩展名只是第一层体验校验，后端仍必须校验 MIME、文件签名、大小、空文件和压缩炸弹风险；第一版不开放带宏 Office 文件和可执行文件。

附件原件与解析正文都按系统默认保存策略写入 MinIO，默认“永久”；系统管理员也可选择“按天保存”并配置 1～3650 天。永久保存的附件不设置到期时间，按天保存的附件由定时清理任务同步删除对象和元数据。运行态预览沿用交付物预览的侧边抽屉交互：`docx` 使用 Word 渲染器，`xlsx/xls` 使用工作簿 Sheet 预览，PDF、图片和纯文本使用各自前端适配器；旧版 `doc` 或其他浏览器无法还原的格式在识别成功后展示解析正文，否则只提供受保护下载。预览、下载与删除都通过后端复核租户、运行、节点、待办和操作者权限，不返回对象存储键或签名地址。

系统附件配置提供三种可选择的识别方式，输入节点统一继承系统设置，第一版不允许流程设计者绕过平台治理自行指定引擎：

| 识别方式 | 协议值 | 行为 |
| --- | --- | --- |
| 简单识别 | `local` | 只使用 Java 本地解析器，不调用 MinerU；遇到本地不支持的格式按字段失败策略阻断或告警放行 |
| 复杂识别 | `mineru` | 白名单内文件直接交给 MinerU，适合统一要求版面识别的场景 |
| 混合识别 | `hybrid` | 本地支持的格式优先提取；失败或无文字时，按 MinerU 白名单升级识别；其他白名单类型直接调用 MinerU |

简单识别的本地能力如下：

| 文件 | 首选解析器 | 说明 |
| --- | --- | --- |
| `txt` / `md` / `csv` | Java 本地解析 | 做编码、行数和最大字符数限制；CSV 生成可读表格文本 |
| `docx` | Apache POI | 提取段落与表格；失败时仅对实际为旧 Word 的原字节尝试 DOC 兼容解析，不执行宏和外部链接 |
| `xlsx` / `xls` | Apache POI XSSF / HSSF | 按 Sheet 提取单元格与公式显示值，不执行公式；大表使用流式读取和行列上限 |
| 电子版 `pdf` | PDF 文本提取器 | 提取到非空正文时直接使用；混合模式无文字时可升级 OCR，减少普通电子文档的延迟与成本 |
| 扫描 `pdf` / 图片 | 简单识别不支持 OCR | 按字段失败策略阻断或告警放行，不允许在简单模式下临时调用 MinerU |
| 旧版 `doc` | Java 可做基础文本提取 | 简单模式不保证复杂表格、浮动对象和版式还原 |

所有解析器统一输出“附件元数据 + Markdown 正文 + 结构摘要 + 解析状态”，下游智能体不关心实际解析器。解析正文属于不可信业务数据，进入模型上下文时必须使用明确数据边界包裹，不能拼入 system prompt 或被解释为平台指令；超长内容按系统字符 / Token 预算截断并标明截断状态。

系统管理新增“系统配置”页签，第一项为“附件识别”。它维护平台级启停、识别方式、单文件 / 单字段上限、解析文本上限，以及默认为“永久”的文件保存策略；选择“按天保存”后再配置保留天数。选择简单识别时，页面明确展示只读的内置扩展名列表 `txt/md/csv/pdf/doc/docx/xls/xlsx`，并提示扫描 PDF 不支持 OCR、图片和 PowerPoint 不支持简单识别。选择复杂识别或混合识别时，额外选择 MinerU 旧版或 MinerU 4.1.7 解析器，并维护服务根地址、加密 API Key 和超时；旧版显示 backend、解析方式、语言及表格 / 公式开关，4.1.7 显示解析档位及 OCR 模式。两者均提供由系统管理员自定义的“复杂识别支持的扩展名”。

系统内置 Word、Excel 交付能力也支持“永久 / 按天保存”的文件保存策略。永久保存的交付结果不生成到期时间；按天保存仍支持 1～3650 天，并由交付文件清理任务删除到期对象。历史交付能力仅配置 `retentionDays` 时继续按天保存，避免升级后意外改变已有数据保留边界。

| 系统配置 | 协议字段 | 说明 |
| --- | --- | --- |
| 启用附件识别 | `recognitionEnabled` | 关闭时仍可按字段上传附件，但不生成解析正文 |
| 识别方式 | `recognitionEngine` | `local` 简单识别 / `mineru` 复杂识别 / `hybrid` 混合识别 |
| 最大文件大小 | `maxFileSizeMb` | 平台单文件硬上限 |
| 文件默认保存时间 | `retentionPolicy` | 默认 `permanent` 永久；可选 `days` 按天保存 |
| 按天保存天数 | `retentionDays` | 仅 `retentionPolicy=days` 时生效，范围 1～3650 天 |
| 复杂识别支持的扩展名 | `mineruSupportedExtensions` | 系统管理员自定义；复杂识别和混合识别的文件外发白名单 |
| MinerU 端点 | `mineruEndpoint` | 自部署 MinerU 或客户兼容端点根地址 |
| MinerU API Key | `mineruApiKey` | 可选，加密保存且不回显 |
| MinerU 解析器 | `mineruParser` | `mineru` 旧版或 `mineru4`（4.1.7）；复杂及混合模式共用所选解析器 |
| 4.1.7 解析档位 | `mineruTier` | `flash` 快速 / `basic` 基础 / `standard` 标准 / `advanced` 高精度，默认标准 |
| 4.1.7 OCR 模式 | `mineruOcrMode` | `auto` 自动 / `txt` 文本提取 / `ocr` 强制 OCR，默认自动 |
| MinerU Backend | `mineruBackend` | 如 `pipeline`、`vlm-auto-engine`、`vlm-http-client` 等 |
| MinerU 解析方式 | `mineruParseMethod` | `auto` / `txt` / `ocr`；这是 MinerU 内部参数，不代表 Agentum 自动选择引擎 |
| 解析语言 | `mineruLanguage` | 默认 `ch`，按实际 MinerU 端点支持值填写 |
| 公式 / 表格识别 | `mineruEnableFormula` / `mineruEnableTable` | 仅旧版解析器使用；4.1.7 由档位决定 |
| 超时 | `mineruConnectTimeoutSeconds` / `mineruReadTimeoutSeconds` | 连接与长耗时解析分别配置 |

MinerU 4.1.7 按创建任务、按需上传、轮询、下载逐文件结果 ZIP 并读取 Markdown 执行；解析总超时覆盖全部步骤。PDF 与图片使用所选档位；Office、OpenDocument、RTF、EPUB、OFD、HTML、CSV/TSV 按服务要求使用 Flash 整本解析。所选档位需要服务端准备对应模型，表格和公式能力由档位决定，不发送旧版 backend、语言或识别开关。4.1.7 与旧版共用当前服务地址、密钥和白名单，切换时应确认连接信息。新版健康测试访问 `/v1/health`，校验健康状态，并在识别到 4.0 服务时明确提示协议不匹配；只确认服务状态，不代表文件解析和所有档位已验收。

复杂识别扩展名以不带点的小写值保存，界面使用标签输入或逗号分隔输入，建议初始值为 `pdf,png,jpg,jpeg,bmp,gif,tiff,webp,docx,xlsx,txt`。在复杂模式下，该列表是 Agentum 是否接受并发送文件到 MinerU 的权威白名单，不根据内置格式表自动删减；系统管理员加入 `doc`、`xls` 或其他扩展名后，运行时同样全部发送给 MinerU。若实际 MinerU 端点不支持，解析结果进入失败态，不允许静默改用 Java 解析。输入节点的 `allowedExtensions` 只能从当前识别方式的系统支持列表中收窄。

混合模式的系统支持列表为本地类型与 MinerU 白名单的合集；字段白名单仍只能收窄。仅白名单内的类型可以外发，未获准外发的文件在本地失败后明确失败，不扩大外发范围。MinerU 回退失败时保留失败状态，不能把空正文标记为成功。简单模式仍完全不调用 MinerU，原有配置不自动切换。

DOCX 误标兼容在上传校验和本地解析两层协同处理：除 ZIP 格式外，仅接受具有 WordDocument 和 0Table/1Table 流且不包含 EncryptedPackage 的 OLE 文档；保留原件与文件名，按真实 DOC MIME 使用解析正文预览。该能力不修复任意损坏文档。解析结果和运行态附件引用记录实际解析器 `parserType` 与回退原因 `fallbackReason`，界面展示兼容或升级识别的路径。

第一版“测试连接”只探测健康状态；上传非敏感样例的逐格式“解析测试”列入稳定化工作，用于验证真实解析与结果读取全链路。扩展名加入复杂识别白名单前仍应在目标环境完成对应格式样例联调，测试不替代运行时错误处理。密钥只允许覆盖更新，查询接口不得回显明文。

定时任务第一版不支持在触发时上传新附件：发布版本中只要存在附件字段，无论必填或选填，都禁止创建或更新定时任务。定时任务创建或修改时固定绑定当时的当前可用工作流版本，后续人工切换流程可用版本不会静默改变已有计划。附件绑定具体流程运行和输入节点，不能把浏览器临时上传 ID 跨运行复用；需要附件的流程应由用户人工发起。后续若需要固定材料，应引用有版本的知识资产或专门的固定附件资产。

运行时日期变量统一使用明确名称：`current_year`、`current_year_month`、`previous_year_month`、`current_month`、`current_month_padded`、`current_day`、`current_day_padded`。其中带 `_padded` 的月份和日期固定输出两位数字；不再提供含义重复的 `year`、`month`、`day`。

授信报告这类流程的推荐链路：

```text
输入授信公司全称
  -> 智能体识别缺失信息并追问
  -> 并行调用 MCP 获取工商、司法、财务和行业数据
  -> 多个章节智能体并行生成报告章节
  -> 报告组装智能体统一口径和格式
  -> 用户审查确认
  -> 生成并交付正式文档
```

交互规则必须区分“模型文本”和“事实数据”：

- 模型生成的分析、章节、措辞和摘要可以支持重新生成、追问修改或人工改写后继续。
- MCP 查询、数据库读取、司法记录、财务指标等事实类数据不能让用户通过追问直接改写；只能重新获取、补充来源或进入人工审核说明。
- 每个积木都要展示当前任务、输入参数、输出参数、可执行动作和下一步去向，弥补开源模型在长任务规划、状态保持和工具约束上的不足。
- 智能体集群节点应优先服务三类场景：协同处理（所有子智能体独立产出并汇总）、接力处理（按顺序传递前序输出，后续智能体可引用前序变量）和意图分派（先按设计态意图路由清单把输入归类为白名单 `intentCode`，再只执行命中的子智能体）。意图路由由业务人员配置“什么时候命中”和目标子智能体，模型只能返回 `intentCode`，不能直接指定 `agentId` 或未绑定能力；未命中时可选择中止提示、转交指定智能体或回复固定话术。集群最终输出变量默认 `cluster_result`，输出模板只组合本节点子智能体输出；多个意图命中时按意图清单顺序执行，未命中的子智能体占位按空值处理。成员启用的结构化对象作为额外输出单独声明，三种执行模式的编辑与发布校验均接受这些已配置对象；意图模式的普通文本仍统一使用集群最终输出，不能直接暴露子智能体文本。结构化对象只有对应成员实际执行后才产生，依赖该对象的交付应匹配执行条件。

工作流由固定节点类型组成。固定节点降低复杂度，能力复用来自节点引用的资产。

交付节点的“交付项数量”和“交付方式”分层配置：单个交付项先选择直接交付或能力交付，再通过右侧抽屉维护模板；多个交付项时，交付方式下沉到每个交付项自身，允许同一个交付节点内混排直接交付、Word 文档、Excel 工作簿、邮件或 Webhook 等能力交付。多交付可选择全部交付项都执行，或按触发规则执行指定交付项；当前触发规则包括始终触发、命中某个智能体集群子智能体、输入节点字段等于固定值、单智能体节点有输出内容。运行态和产品交付页只展示本次实际触发并生成记录的交付物，未触发的模板和交付项不占位展示。

| 节点 | 作用 | 是否可暂停 |
| --- | --- | --- |
| 触发节点 | 手动、定时、Webhook 或外部事件触发流程 | 否 |
| 用户输入节点 | 表单、文件上传、人员选择、部门选择、补充说明 | 是 |
| 智能体节点 | 调用智能体模板执行分析、生成、判断、提取或追问 | 可选 |
| 并行节点组 | 同时启动多个子智能体或工具任务，加快数据获取 | 取决于子节点 |
| 合并 / 组装节点 | 汇聚并行结果，透传、JSON 合并、模板组装或调用组装智能体 | 可选 |
| 条件分支节点 | 基于变量、规则或外部返回值决定路由 | 否 |
| 人工审核节点 | 人工确认通过；修改使用运行详情的回退能力 | 是 |
| 交付节点 | 生成文件、发送邮件、创建 OA、推送 IM、Webhook、写数据库 | 否 |
| 结束节点 | 结束本次运行并固化结果 | 否 |

并行节点的本意是放入多个子智能体或工具任务并发执行，例如“资料核验智能体、外部数据查询智能体、风险补充分析智能体”同时运行。合并节点负责把它们的输出组装为下游可用变量，必要时可以绑定“报告组装智能体”。

输入节点、条件节点、结束节点这类不依赖智能体的通用节点，建议平台内置。是否也作为“能力资产”管理，后续可根据复用和版本治理需要再决定；第一阶段先按内置节点处理更简单。

## 6. 能力资产

能力资产是流程设计的复用来源。流程节点不复制资产内容，而是引用资产版本。

第一阶段能力资产范围：

- 智能体模板。
- Skills。
- MCP。
- 提示词模板。
- 交付能力资产。

暂不展示知识库资产。

能力资产分为两层：

- 源码 / 实现层：放在仓库 `capabilities/` 目录下，保存产品运行时 Skills、自研 MCP Server 和交付适配实现。提示词模板功能保留在能力资产与前端配置链路中，当前不再维护独立源码目录。
- 资产 / 分配层：放在数据库和管理页面中，保存资产名称、版本、发布状态、引用关系、租户可用能力池、租户内分配范围和运行安全策略。

这两层不能混为一个概念。`capabilities/skills/` 和 `capabilities/mcp-servers/` 负责让能力能被开发、测试和部署；能力资产页负责让这些能力被登记、发布、停用、版本化和追溯。

`.codex/skills/` 是开发本项目时给 Codex 使用的本地辅助技能，不是 Agentum 产品运行时的 Skill 资产来源。

系统能力分配采用“可用能力池”模型，不再拆成“查看、使用、执行、管理”等动作权限。系统管理员把平台能力放入某个租户的可用能力池；租户管理员再把这批能力分配给用户、部门或角色。分配完成后，用户在能力资产页、智能体模板和流程设计中自然可见并可用。

“我的能力”需要区分草稿和正式能力。用户新建时只生成“能力草稿”，完善后发布为正式能力，流程设计再引用正式版本。用户自建能力分别配置读取 / 使用范围与内容编辑范围，两部分都支持仅自己、指定同事、全体同事；编辑权限自动包含读取权限，只有创建者可以配置权限和删除能力。获得编辑权限的同事可以维护草稿、发布或改回草稿，但引用能力时仍按其自身权限复核。能力之间的相互引用只允许指向已发布版本，草稿不能被其他能力或流程引用。后续接入引用关系后，已被草稿、发布流程或运行快照引用的能力必须禁止删除。第一阶段从安全边界出发，业务用户只允许创建提示词模板和智能体模板；Skill、MCP 和交付能力仍由系统管理登记并通过可用能力池分配。

提示词模板草稿编辑时保存提示词正文、适用场景和版本信息。智能体模板草稿编辑时保存系统提示词，可从「对我开放」的已发布系统提示词或本人已发布的提示词模板组装，也可直接自定义系统提示词；同时只能从当前主体已开放的 Skill 和 MCP 中选择构建材料。后端保存与发布前必须重新校验这些引用仍满足“仅引用已发布能力”和当前主体能力池边界，避免用户通过手写 ID 绕过租户分配和运行安全边界。

能力资产页面应聚焦“资产是什么、版本是什么”。业务用户侧「对我开放」页签展示租户分配的系统能力，以及同事通过读取或编辑权限开放的用户自建能力；系统能力保持只读，自建能力按当前访问级别进入只读详情或协作编辑。租户可用能力池、人员 / 部门 / 角色分配和凭证策略仍放到系统管理和租户管理中。

能力资产页不建议展示“流程导入建议”这类设计指导。流程节点如何引用资产，应放在流程设计的节点配置面板中。能力资产页应提供新增、发布、停用、版本管理和查看引用关系等入口；其中「对我开放」以只读查看为主，「我的能力」承担草稿编辑与发布。

如果每类资产模块已经提供独立新增入口，就不应再额外保留一个泛化的“资产创建入口”。右侧或辅助区域更适合展示待治理资产、引用关系、缺失授权、草稿待发布和高风险能力缺少审批策略等运营信息。

### 6.1 交付能力资产

交付能力也应成为可治理资产。

示例：

| 交付能力 | 说明 | 风险 |
| --- | --- | --- |
| Word / Excel / PDF 生成 | 根据模板和变量生成正式文档或表格文件 | 中 |
| 邮件发送 | 发送正文和附件，可接 Mailpit 本地验证 | 高 |
| OA 流程创建 | 创建审批或归档流程 | 高 |
| IM 推送 | 推送飞书、钉钉、企微消息 | 中 |
| Webhook 回调 | 回调外部系统 | 中 |
| 数据库写入 | 写入业务表或结果表 | 高 |

高风险交付能力必须支持审批、二次确认、审计和失败重试。

交付能力按实现来源分为两类：

- 系统内置交付能力：由 Agentum API / Worker 原生实现，例如当前阶段的邮箱发送、Word 文档生成和 Excel 工作簿生成。系统内置能力可以直接使用平台的凭证加密、权限校验、交付记录和审计能力。
- 自定义交付适配器：放在 `capabilities/delivery/` 目录下，通过统一 Manifest 声明配置、输入、输出、风险等级和调用入口，再由系统管理登记测试并放入租户可用能力池。

## 7. 系统管理与租户配置

系统管理是平台级入口，负责“哪些底层能力可以被登记、测试，并在具体租户中启用”。

推荐链路：

```text
系统管理员注册并测试底层能力
  -> 在某个租户的配置抽屉中放入租户可用能力池
  -> 租户管理员在当前租户内分配给用户、部门或角色
  -> 用户在能力资产、智能体模板和流程设计中自然可见并可用
  -> 流程发布后，业务用户直接使用流程，不需要理解底层能力分配
```

能力分配只回答“这项能力是否进入当前主体的可用范围”。高风险 MCP、外部交付、数据库写入、敏感文件下载等仍需要运行安全策略，例如审批、二次确认、额度、凭证注入、脱敏和审计；这些策略不属于能力分配动作矩阵。

系统管理负责：

- 租户管理。
- 模型供应商和模型供应商类型。
- 全局 MCP 注册、测试、启停。
- 全局 Skills 和提示词模板上架。
- 全局交付能力注册。
- 在单租户抽屉中维护“租户可用能力池 / 模型分配”。
- 凭证策略和安全策略。
- 多租户隔离、资源配额、数据保留策略。

租户管理负责：

- 用户、部门、角色和成员。
- 组织生命周期勾稽：停用部门、租户内角色或成员前，若仍被页签分配（`page_grants`）或能力分配（`resource_grants`）引用则阻断；删除部门/角色时同样检查引用；调整部门上级时禁止形成组织环。租户内业务角色（`roles`）用于组织与授权主体，登录入口（`user_role_assignments` 的 `business` / `tenant_admin`）与页签可见性（`page_grants`）是不同层，需分别配置。
- 当前租户可用能力池向用户、部门或角色的二次分配。
- 哪些用户、部门或角色可以进入业务工作台、流程设计、能力资产、运行审计等模块和页签。
- 哪些流程模板、智能体模板、运行记录和交付物进入当前主体的可见范围。
- 高风险能力在运行时是否需要审批、二次确认、额度限制或审计加严。

第一阶段把“租户内管理”明确命名为租户管理。也就是说，系统管理员负责平台级租户创建、启停、全局能力登记测试，并在系统管理的单租户抽屉中维护租户可用能力池和模型分配；租户管理员负责当前租户内的组织、模块入口、需求配置和能力池分配。

系统管理生产页面建议在左侧进入“系统管理”大模块后，再按模块内页签或顶层菜单组织：

- 概览：用少量卡片说明平台租户数、启用能力、模型供应商、异常授权和待处理风险，只作为进入具体管理模块前的摘要。
- 租户管理：租户创建、启停、基础信息、租户状态、配额和数据保留策略。支持在抽屉中配置租户可用能力池、模型分配、成员角色诊断和默认信息。
- 能力管理：全局 MCP、Skills、提示词模板、交付能力的注册、测试、启停和版本治理；模型不作为全局能力登记。
- 模型管理：供应商、模型、额度、默认模型和密钥脱敏状态。

租户管理生产页面建议在左侧进入“租户管理”大模块后，再按模块内页签或顶层菜单组织：

- 概览：展示当前租户成员数、部门数、角色数、待配置入口、能力池缺口和近期风险操作。
- 人员组织：用户、部门、成员关系和账号状态。
- 角色与入口：业务角色、模块入口、页签范围和审计可见性。
- 能力分配：把租户可用能力池分配给用户、部门或角色，分配后前端可见即能用。
- 资源范围：工作流、智能体模板、运行记录、交付物面向哪些用户、部门或角色可见。
- 需求配置：租户内流程需求、表单字段、审核规则、交付目标和可用能力约束。
- 租户内审计：当前租户内成员变更、权限变更、能力分配和敏感操作记录。

权限设计必须保留平台级系统管理与租户内管理分层：系统管理员 / 租户管理员路由分层、JWT + 租户上下文 + 角色校验、部门 / 角色 / 成员管理、租户模型和系统配置管理都应围绕 Agentum 自身的业务边界展开；在 Agentum 中，租户内管理入口命名为“租户管理”。

## 8. 租户管理中的权限管理

权限模型采用：

```text
认证身份 + 租户上下文 + 组织 / 部门归属 + RBAC + 模块入口 + 资源范围 + 能力池分配 + 运行安全策略 + 审计
```

推荐角色：

| 角色 | 说明 |
| --- | --- |
| 系统管理员 | 管理全局配置、租户、模型、全局 MCP、交付能力 |
| 租户管理员 | 管理当前租户内用户、部门、角色、需求配置、资源范围和可用能力分配 |
| 流程设计者 | 创建和编辑工作流、配置节点、测试运行 |
| 智能体管理员 | 创建、维护和发布智能体模板 |
| 能力管理员 | 管理 Skills、MCP、提示词模板和交付能力资产 |
| 审核人 | 处理人工审核节点和高风险审批 |
| 执行人 | 发起流程、填写输入、追问确认、查看自己的结果 |
| 观察者 | 只读查看被分配范围内的流程、资产或运行记录 |

系统能力分配不设计“查看 / 使用 / 执行 / 管理”动作矩阵。系统管理只决定系统能力是否进入租户可用能力池；租户管理只决定这批系统能力分配给哪些用户、部门或角色。用户自建能力的读取 / 使用和内容编辑范围由创建者在能力详情中配置。

流程、运行记录、交付物和审计仍然需要模块入口和资源范围控制。例如谁可以进入流程设计、谁可以发布流程、谁可以处理审核、谁可以查看审计证据链，这些属于业务模块权限，不应混入能力资产授权动作。

敏感能力的审批、二次确认、额度、凭证注入、脱敏和审计属于运行安全策略。它们用于保护高风险 MCP、外部交付、数据库写入、敏感文件下载等调用，不改变“能力分配后可见即能用”的产品心智。

第一阶段以三类登录入口作为第一重权限：

- 业务用户：进入业务侧工作区，可承载业务工作台、流程设计、能力资产、运行审计等大模块；实际能看到哪些模块、页签、流程和资产，由租户管理里的第二重配置决定。
- 租户管理员：进入租户管理，管理当前租户内成员、部门、角色、菜单、资源范围、需求配置和能力池分配。
- 系统管理员：进入系统管理，管理平台租户、全局能力登记测试、模型供应商、租户可用能力池 / 模型分配和凭证策略。

一个用户可以同时拥有多个角色或多个租户身份，必须设计角色 / 租户切换。切换时应重新计算活跃租户、活跃角色、左侧菜单、模块内页签、资源范围和可用能力池；前端只做展示切换，后端必须在每次接口调用时按 token、租户上下文、角色、部门、人员分配和资源范围重新校验。

菜单权限分两层：

- 第一层是登录入口角色：`business`、`tenant_admin`、`system_admin`。它决定用户进入业务侧、租户管理还是系统管理，不等同于租户内业务职务。
- 第二层是租户内配置：租户管理员按用户、部门、租户自定义角色分配业务工作台、流程设计、能力资产、运行审计等大模块、模块内页签、资源范围和可用能力池。用户没有被分配对应模块、页签或资源时，前端不展示，后端仍按资源范围复核。
- 模块内页签 / 顶层菜单表示当前大模块内部的详细功能区，例如租户管理里的人员组织、角色与入口、能力分配、资源范围、运行安全策略、租户内审计。它们不是全局顶层菜单，也不应全部做成首页卡片入口。

租户管理员负责当前租户内的入口、资源范围和能力池分配，可以按角色、部门、人员三个维度配置。人员级分配用于补充特殊职责，必须有原因、有效期和审计记录，避免绕过角色 / 部门策略后不可追溯。

租户管理的治理配置建议按页签组织：

- 人员组织：用户、部门和成员关系。
- 角色与入口：角色能进入哪些业务模块和模块内页签。
- 能力分配：租户可用能力池分配给哪些用户、部门或角色，分配后可见即能用。
- 资源范围：具体流程、智能体、运行记录、交付物面向哪些用户、部门或角色可见。
- 运行安全策略：高风险 MCP、外部交付、敏感文件下载、凭证申请和审批。
- 审计可见性：谁可以查看只读证据链，以及哪些字段需要脱敏。

凭证配置和凭证明文读取不属于租户管理的主要职责。系统级凭证策略、模型密钥和全局 MCP 凭证放在系统管理；租户管理只决定当前租户内能力池如何分配，以及高风险调用是否需要申请、审批或审计加严。

## 9. 运行态交互

运行态是 Agentum 的核心体验，应围绕“当前步骤”而不是“聊天历史”组织。

必须支持：

- 暂停：等待用户输入、追问、人工审核、外部回调或高风险审批。
- 恢复：提交表单、确认结果、审核通过、审批工具调用后继续。
- 追问：用户围绕当前智能体结果继续问，确认后写入最终变量。
- 改写：用户要求智能体重写当前节点输出，但仍受输出 Schema 约束。
- 回退：有权限时退回到上一个可回退节点，并保留审计记录。
- 退出：用户离开页面后可从待办或运行记录恢复。
- 重试：节点失败后按策略重试，并记录重试原因和结果。
- 子智能体重新执行：已完成的智能体集群允许只重跑某个子智能体；协同处理保留其他结果，接力处理从目标开始连带重跑后序依赖，意图分派沿用本次运行原命中范围。

运行详情应展示：

- 当前状态。
- 当前节点。
- 等待对象。
- 暂停原因。
- 输入变量和输出变量。
- 已完成步骤摘要。
- 工具调用摘要。
- 审核记录。
- 交付记录。
- 最终交付物。

业务用户看到简化步骤条，设计者看到阶段积木配置，审计人员进入只读证据链。

### 9.1 审核、监控与审计边界

“审核”和“审计”必须分开：

- 审核是业务流程中的人工节点，由审核人或流程负责人确认通过；修改通过运行详情回退处理。
- 运行监控是管理员视角，用于查看运行状态、处理失败重试、取消和补偿，所有介入动作都必须写入审计。
- 运行审计是只读证据链，用于还原流程当时发生了什么，不推动业务流程继续。

运行审计可以展示执行链路、节点输入输出快照、变量快照、MCP 调用摘要、模型输出解析、审核记录和交付记录。它们的意义是追溯“结论从哪里来、谁在什么时候做了什么、敏感数据是否脱敏、工具调用是否越权”，不是让审计人员修改当前流程。

“执行链路”是聚合视图，不是新的独立数据源。它应由 `WorkflowRun`、`NodeRun`、`WaitingEvent`、`RunEvent` / `audit_logs`、`mcp_call_logs`、`delivery_records` 和 `variable_snapshots` 组合生成。审计日志是证据来源之一，但不应被设计成承载所有执行状态的万能流水表。

暂停恢复按钮不应出现在纯审计页。提交输入、审核通过、交付确认等恢复动作应出现在业务运行详情或我的待办详情中；管理员取消、重试、补偿应出现在运行监控中。

## 10. 第一阶段完成闭环

第一阶段已完成一个可演示、可验证、可扩展的基础治理闭环：

```text
用户输入 -> 智能体分析/追问 -> 并行子智能体获取数据 -> 合并组装 -> 人工审核 -> Word/Excel/邮件/Webhook 交付 -> 审计证据链
```

第一阶段完成边界：

- 登录和当前用户 / 租户 / 角色上下文。
- 用户、部门、角色、成员和权限策略基础管理。
- 工作流草稿、固定节点类型、阶段积木和右侧配置面板。
- 智能体模板、Skills、MCP、提示词模板和交付能力基础资产。
- 变量声明、上游引用和输出 Schema。
- 并行节点组和合并节点。
- 暂停、恢复、追问、审核、重试。
- 运行详情和审计证据链。
- 系统内置邮箱、Webhook、Word 文档和 Excel 工作簿交付。
- PostgreSQL + Flyway 数据库版本管理。

后续个性化集成和平台增强不再作为阶段一验收项；**知识资产**作为阶段二主线单独推进：

- 知识资产（文档解析、检索、引用与审计）。
- OA、PDF、IM、数据库写入等企业个性化交付通道。
- 插件市场。
- 复杂嵌套子流程。
- 多模型自动路由。
- 完整企业 SSO / MFA。
- 高级报表分析和成本优化。


## 新增文件模板交付

Word / Excel 交付项可主动选择“填写文件模板”；没有选择时，已有 Markdown 转 Word、按 Sheet 内容生成 Excel 的配置与执行方式不变。模板入口位于“能力资产 → 交付模板”，也可在交付项中直接上传和管理。原件支持 `.docx` / `.xlsx`，最大 20 MB。

生成方式使用“按内容生成”和“填写文件模板”两个用途名称，并按当前选择显示简短说明：前者根据正文、Sheet 内容或数据区域配置生成新文件，后者按已有文件中的字段标记填充并保留模板布局和样式。

格式配置以方案为入口：先新增金额、汇率、文字、普通数字、日期、是/否或自定义方案，再跨 Sheet 多选应用字段。金额同时设置数字类型和 `#,##0.00`，汇率默认六位小数，日期默认 `yyyy-mm-dd`；文字保留账号和编号的原值。字段选择提供名称/标识搜索、Sheet 筛选、当前结果全选、明细分组全选及按名称推荐，不依据看似数字的实际值猜测编号。方案可调整样式、查看已选字段与删除，同一完整字段标识只归属一个方案，移入新方案时从原方案移出；同一字段的多个填写位置统一生效。

字段设置另有批量预设入口，可勾选多个普通字段/明细列后统一设为金额、文字等类型，金额等预设同时生成格式方案。单独改变字段类型会移出不兼容方案，避免保存互相矛盾的配置；原必填、条数限制、内容要求和未选字段保留。试填值仅在类型改变时适配，合法数字、零与空位保留，原数据集不改写。结构化结果字段编辑也支持批量类型设置，金额和汇率在结构化对象中均采用数字类型。

全局、Sheet 和单独位置样式收进高级设置，继承顺序为原件 → 全局默认 → Sheet 默认 → 字段方案 → 单独位置 → 流程覆盖。行高和列宽仍作用于整行、整列；删除方案不回退已确定的字段类型。修改发布模板后需保存并发布新版本，在交付项中明确选择该版本，已有运行不会自动换模板。

字段配置按项折叠，标题直接显示类型和必填状态，模板固定标识不再重复渲染为禁用输入框。页签复用消息中心的模块切换容器；创建者可直接编辑自己的模板；编辑发布版本后保存为新版本草稿，已有流程固定的发布内容保留。共享他人的模板仅可查看或复制为独立模板。字段和明细列提供全部设为必填/选填的批量入口。试填的短字段并列排布、文本框随内容增高，多段正文和明细独占一行；数字、日期、选项和布尔值使用相应控件。明细通过紧凑行卡片添加、删除；上传与替换原件使用主题文件卡片显示文件名、格式和大小限制。

模板用 `{{company_name}}` 标记固定位置，表格样板行用 `{{risk_items[].category}}` 标记列表及数据列。字段负责内容类型和约束，位置负责样式；同一字段可以在 Word、多个 Sheet 和多个单元格中分别设置格式。格式支持保留原样、应用预设或局部覆盖，优先级为默认填充样式、Sheet 默认样式、模板位置样式、交付项位置覆盖。空白表示沿用，显式关闭或填写 0 表示取消对应属性。

填写标记中的字段标识以小写英文字母开头，仅包含小写字母、数字和下划线；中文业务名称可在字段配置中设置。原件未包含标记时，需先编辑文件并重新上传。模板列表加载及上传、替换、保存、发布和试填失败统一使用顶部浮动消息，避免抽屉内操作的错误显示在背景列表中。

流程设计的交付项配置显示当前 Word / Excel 类型、上传发布顺序，并提供可展开的填写规则、明细方向、MCP 数据集绑定和公式重算说明；该配置区的加载、类型选择和试填错误也使用顶部浮动消息。模板列表和配置抽屉共用主题卡片、紧凑页签与独立滚动区，内嵌模板库保留四周留白和底栏。模板中的“字段说明”解释含义和取数口径，供绑定来源参考，不自动过滤、计算或改写数据；智能体结构化输出中的“内容要求”会进入模型字段说明。实际硬校验由必填、类型、枚举、字数和条数设置完成。

内容来源可以是上游输入、单智能体、集群子智能体的独立输出、系统变量或固定内容。一个智能体可额外输出一个包含多个字段的业务对象，原文本变量继续保留。来源控件按节点、输出对象、内部字段选择；明细列按字段标识取值，名称相同时默认对应，名称不同时显式映射，与来源列的排列顺序无关，空值保持记录位置。文件模板的文件名支持下拉插入系统、输入和上游对象中的标量字段，例如 `金融月报-{{report_year}}-{{attachment_meta.data_date}}.xlsx`；运行当天的 `date` 与报告月份区分显示，未取得变量值时明确提示。每个模板字段只绑定一个明确来源，移除追加内容来源和隐式拼接；需要合并数据时由上游明确完成。

新增结构化结果只在启用时校验：完整 JSON / 唯一外层 JSON 围栏、重复键、尾随文本、必填、类型、枚举、字数、条目及允许的 Markdown 内容。模型可在当前执行预算内最多修正三次；失败不能伪装成普通文字成功。追问候选数据与正式数据分离，采用回答时同步选择其数据；手工编辑新增模式使用业务字段表单，原文本编辑方式不变。

多段正文使用文字数组，每项形成独立段落并继承样板段落属性，可覆盖首行缩进等格式；单项中的换行是段内换行。多段或 Markdown 标记须独占段落。Word 支持正文、页眉页脚、普通表格和简单样板行；文本框填写、嵌套重复、跨行合并不属于首批范围。Excel 单元格使用文字、段落组、数字、日期、布尔值；Markdown 表格应由上游显式转换为结构化明细，再绑定表格区域。空的可选明细在 Word 和 Excel 中均保留一个空样板行；可选 Markdown 留空时不插入兜底正文。

模板草稿仅创建者可见、可编辑；发布内容可选择仅自己或租户内共享。创建者默认可编辑，修改发布内容后保存为本模板下一版本草稿，发布行保持不变；没有变更的保存不增加版本。同一模板已有草稿时继续编辑该草稿，避免覆盖未发布修改。复制一律创建独立模板，名称追加“副本”，版本从 1 开始。模板库每个模板只展示最新可见版本，配置内分页查看历史。替换原件会重新识别字段并重置格式，发布版替换同样形成新草稿。创建者可删除整个模板及版本链，库和新选择列表不再展示，已有流程固定引用的版本继续可读、可交付。流程引用固定版本，更换模板必须重新确认绑定；旧运行和旧流程不会自动切换。跨环境导入流程后，如模板引用不可访问，需要上传并重新绑定模板。

试填使用独立测试数据，不运行 AI、不生成正式交付记录。Excel 明细行高默认按实际内容估算适配，可选择沿用模板或固定磅值，避免把标记编辑时的高样板行复制到所有记录。试填预览提供行列标题、缩放、独立滚动，裁掉仅格式化的尾部空白，按原件显示边框和合并；最多预览 200 行、40 列。全部 Sheet 填完、引用更新后计算公式缓存，预览与下载共用本次计算结果，悬停可查看保留的原公式。循环引用、#REF!、#VALUE!、除零及无法计算的函数均指出 Sheet/单元格并阻止生成，不输出旧缓存。下载包含完整内容，打印分页及 Office/WPS 兼容效果仍需实际验收。


### MCP 数据集与 Excel 独立数据区域（2026-11）

系统管理的 MCP 配置先获取当前连接的实际工具列表，再下拉选择具体工具设置结果策略。规则可复制到尚未配置的工具，复制保留字段、路径和分页参数，自动生成独立结果名，随后可分别调整；原规则不变。结果策略包括：直接返回、保存为数据集、按体积自动选择。数据集结果在进入模型消息、SSE 和调用日志之前转换为引用及受限预览，可选仅摘要、前 N 条、后 N 条、首尾各 N 条及模型可见字段。未配置工具采用直接返回，超过 256 KB 明确拒绝，提示配置数据集模式。

数据集完整内容保存到对象存储，数据库只保存本次运行、节点、来源能力、条数及实际策略。模型通过内置 `mcp_dataset_query` 查看字段、按可见字段精确筛选和分页读取，单次最多 100 条且内容受 24 KB 限制；累计调用仍受节点执行轮数约束。查询与交付均复核来源能力分配、租户及运行归属。字段白名单限定模型视图；交付可读取经授权的完整数据。

结果提取支持 structuredContent、整个响应或唯一 text 块中的完整 JSON，以及对象字段路径/根数组，不支持任意脚本。自动分页第一期支持顶层页码和每页条数参数、布尔 hasMore 路径及可选 total 路径；暂不支持游标分页、任意排序和聚合查询。数据集整体最多 100000 条、20 MB，取消工具级保留天数，完整结果与流程运行同生命周期；按小时回收已删除流程的结果对象，清理失败保留元信息以便重试。内容存储复用附件对象存储，文件名为 mcp-dataset.json。

智能体完成后，在节点输出 `mcp_datasets.cap_<能力UUID下划线形式>.<结果名称>` 登记本次实际调用引用；集群再以 `member_<成员序号>` 隔离各成员。交付下拉展示上游步骤、成员、MCP 和工具结果，结果名称无需手填；规则可声明结果字段用于列映射。绑定的结果形成执行依赖，模型漏取时要求补取，仍缺失则失败；自动模式被交付绑定时小结果也保存。未命中的集群成员不会冒用其他成员数据。追问沿用正式数据，候选回答保存独立引用，采用回答后切换；重新执行清除正式引用锚点。会话只显示摘要、受限预览及完整 JSON 下载，下载重新复核流程和 MCP 权限。

Excel 内容生成方式在每个 Sheet 下可添加多个独立区域，分别设置开始单元格、扩展方向、来源节点、来源路径、表头开关及列映射。文件模板统一登记所有明细标记，`excelRegions` 的每项包含 Sheet、明细列表、字段 column、原标记 startCell 和 direction；在对应明细卡片内统一或逐位置调整方向，不再另设区域配置。一个列表可跨 Sheet、重复字段或混合方向，始终以原数组的同一索引写入各位置，缺失/null 留空，不压缩、不独立排序。每个位置可选择“推移后续内容”或“仅使用已有空白”。默认根据实际条数为纵向插入整行、横向插入整列；同一样板行/列的并列列表共享最长列表所需的空间，上下表头、小计和说明整体移动。固定模式仍检查实际覆盖和冲突，插入不能切开跨记录合并或已有 Excel 表格。

Excel 汇总页可直接引用明细公式，无需重复填写汇总参数。`SUM('信贷业务'!D3:D1048576)` 跳过前两行但仍包含范围内所有数值，有小计时宜使用表格结构化引用或动态名称。字段位置提供 `rangeName`，留空生成 `data_<列表>_<字段>`，重复位置附序号；可填原件已有的工作簿级名称。生成时按实际数组长度更新范围，中间 null/缺失值保留，表头与合计不计入。Excel 表格需在首个数据行绑定一份纵向明细，生成时更新表格/筛选范围、计算列及各表自己的合计位置，左右表可有不同条数。普通样板中与字段连续相邻的公式视为逐条计算列，固定汇总需放在数据区域外并以空列隔开。

模板公式的地址随整个工作簿布局调整；恰好结束于样板数据的区间引用扩展到实际记录末尾，跨 Sheet 与命名公式同样处理。记录内公式按相对/绝对引用规则复制，字符串常量及结构化引用文本保持。单个直接单元格引用继续表示对应单元格，不自动变为求和区间。表格的 `[@列]` 仅在服务端计算期间解析为当前行，文件中保留原生结构化公式。数组公式、多 Sheet 三维引用、外部工作簿依赖及不支持的函数不做猜测性计算，会明确失败；公式的业务口径仍由模板设计者确认。

MCP 数据集填写模板日期列时兼容 `yyyy-MM-dd` 与 `yyyyMMdd`（含八位整数），统一写为日期值；空值保留，非法日期明确失败，原数据集内容不改写。
